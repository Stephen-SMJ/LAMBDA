# LAMBDA LaTeX Report Skill

Use this guide when the user asks for a long report, publication-style analysis, PDF report, Chinese report, or a document that should look polished rather than like a chat answer.

## When to use LaTeX

Use LaTeX when the user asks for a PDF, long-form report, formal analysis document, paper-style output, or high-quality deliverable. If the user only asks for a quick answer or lightweight notes, use markdown instead.

Before writing the final report, inspect the generated files and include the strongest figures close to the paragraphs that interpret them. Do not put all charts into one generic visualization section.

## Writing Style

Write like an analyst explaining evidence, not like a template. Prefer cohesive paragraphs over bullet lists. Use bullet points sparingly for compact summaries, definitions, or action items. Avoid generic headings such as "Executive Summary" unless the user explicitly asks for them.

Make the report substantial. Explain the findings, uncertainty, caveats, and implications. Use concrete metric values and refer to figures in the text. The report should contain enough narrative that it can stand alone without the chat history.

Use section titles that state findings, for example:

- "Location and area explain most of the price spread"
- "Pollution spikes cluster around Mong Kok and commuting days"
- "The model performs well on mid-range homes but underestimates premium properties"

## Recommended LaTeX Template

For English reports, use `pdflatex`. For Chinese or mixed Chinese/English reports, use `xelatex` and `fontspec`.

The LAMBDA logo is bundled with this skill under `./res/logo.png`. In local mode, the stable compile path is `.skills/res/logo.png` relative to the current working directory. Use that path in generated reports so the logo remains an internal resource and is not uploaded as a user-visible generated file.

Do not simplify or remove the LAMBDA website link from the page header. Every generated LaTeX report should keep the subsequent-page header exactly as `Generated by LAMBDA: \url{https://lambda.com.ai}` unless the user explicitly asks to remove branding.

If the report language is Chinese, do not adapt the English template by only adding `fontspec`. Use the dedicated Chinese template below. It is designed to avoid overfull lines, right-margin overflow, and broken Chinese line wrapping.

## Chinese LaTeX Template

Use this template for Chinese or mixed Chinese/English reports. Compile with `xelatex`, not `pdflatex`.

Important Chinese layout rules:

- Use `xeCJK` with `Noto Sans CJK SC`.
- Keep paragraphs as normal Chinese prose. Avoid long unbroken English strings; if unavoidable, put them in `\texttt{\small ...}` or a table column that can wrap.
- Do not use raw `tabular` for Chinese text tables. Use `tabularx` with `L` flexible columns or `p{...}` widths.
- Keep figures at `0.92\textwidth` by default. Use `\textwidth` only when the figure is already readable and has no clipped labels.
- If a table has many columns, summarize columns or rotate the page. Do not force a wide table past the margin.
- The first page must be fully localized: use `摘要`, the current date from the system prompt such as `2026年5月11日`, and a controlled-width abstract block. Do not leave the default English `Abstract` heading.
- Never copy the example date below. Replace `\reportdate` with today's date from the system prompt.

## Table Rules

Tables must not overflow the page width. Avoid raw `tabular` with many columns. Prefer `tabularx` with `\textwidth`, compact numeric columns, and one or more flexible text columns. Use smaller font only when needed.

Good default table:

```latex
\begin{table}[H]
\centering
\small
\caption{District-level air quality summary}
\begin{tabularx}{\textwidth}{lrrrrY}
\toprule
District & PM2.5 & PM10 & NO2 & AQI & Interpretation \\
\midrule
Mong Kok & 54.7 & 86.2 & 67.9 & 111.7 & Highest average exposure; prioritize deeper temporal checks. \\
Tai Po & 28.6 & 46.2 & 34.7 & 59.6 & Cleaner baseline with fewer high-risk days. \\
\bottomrule
\end{tabularx}
\end{table}
```

For many columns, rotate or scale safely. Use this only when the table is mostly numeric and cannot be summarized:

```latex
\begin{table}[H]
\centering
\scriptsize
\caption{Model diagnostics across feature groups}
\resizebox{\textwidth}{!}{%
\begin{tabular}{lrrrrrr}
\toprule
Model & R2 & RMSE & MAE & Bias & CV Mean & CV Std \\
\midrule
Linear regression & 0.68 & 732000 & 521000 & -12000 & 0.64 & 0.05 \\
Ridge regression & 0.69 & 721000 & 514000 & -9000 & 0.65 & 0.04 \\
\bottomrule
\end{tabular}
}
\end{table}
```

For long row-oriented tables, use `longtable` so the table can continue across pages:

```latex
\small
\begin{longtable}{p{0.22\textwidth}p{0.52\textwidth}r}
\caption{Important observations and supporting evidence}\\
\toprule
Topic & Finding & Value \\
\midrule
\endfirsthead
\toprule
Topic & Finding & Value \\
\midrule
\endhead
Price drivers & Area remains the strongest positive predictor after standardization. & 0.42 \\
Risk segment & High-AQI days concentrate in the central commercial districts. & 31\% \\
\bottomrule
\end{longtable}
```

If a table still looks too wide, summarize it into fewer columns instead of forcing it onto the page. A clear compact table is better than a dense unreadable one.

## Figure Rules

Use full-width figures for most charts:

```latex
\includegraphics[width=\textwidth]{./data/workspaces/<conversation_id>/chart.png}
```

For smaller diagnostic figures, use `0.82\textwidth`. Always use local workspace local paths, not OSS URLs or proxy URLs, when compiling PDF reports.

## Compile Commands

English report:

```bash
pdflatex -interaction=nonstopmode -halt-on-error -output-directory ./data/workspaces/<conversation_id> ./data/workspaces/<conversation_id>/report.tex
```

Chinese or mixed Chinese/English report:

```bash
xelatex -interaction=nonstopmode -halt-on-error -output-directory ./data/workspaces/<conversation_id> ./data/workspaces/<conversation_id>/report.tex
```

Run the compiler twice if the document has a table of contents, references, or cross-references.

## Defaults

If the user does not provide an author, use `LAMBDA`.

If the user does not specify a report language, match the user's language. For Chinese reports, use `xelatex` with `Noto Sans CJK SC`.
